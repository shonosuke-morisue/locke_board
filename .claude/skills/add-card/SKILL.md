# カードの追加

カードのマスター定義は `server/src/gameState.ts` に一元化されている。クライアントはサーバーから配信される状態を表示するだけなので、**通常はサーバー側の定義追加と CLAUDE.md の更新だけで完結する**。

## 1. どちらの編か確認する

不明なら追加先（惑星編 / 秘密基地編）をユーザーに確認する。

| 編 | 定義配列 | 場所の目安 | 要素の型 |
|---|---|---|---|
| 惑星編 | `CARD_DEFINITIONS` | `gameState.ts` 69行目付近 | `{ name, count, content, isAbility }` |
| 秘密基地編 | `BASE_CARD_RAW` | `gameState.ts` 32行目付近 | `{ name, count, content }`（全カード `isAbility: false`） |

## 2. 定義配列に要素を追加する

- `name`: カード名。**惑星編の能力カードは名前を `[能力]` で始め、`isAbility: true` にする**（秘匿ロジックは名前ではなく `isAbility` フラグで判定される）。
- `count`: 枚数。
- `content`: 効果説明文。複数行は `\n` で改行する。
- 既存要素のフォーマット（インデント・整列）に合わせる。

## 3. デッキ枚数の整合を確認する

- 惑星編は全カードをシャッフルし**先頭36枚**を 6×7 ボード（宇宙港列を除く6列×6行）に配置する。
- 秘密基地編は全カードをシャッフルし**先頭36枚**を 6×6 ボードに配置する。
- どちらも**合計が36枚以上**である必要がある（既存の合計は惑星編78枚・秘密基地編52枚なので、追加・削除で36を下回らないこと）。枚数を減らす依頼のときは特に注意する。
- 新しいフィールドが必要なカードを足す場合は `server/src/types.ts` の `CardData` と、クライアント `client/src/types/game.ts` の `Card` 型、および表示側（`client/src/components/Card.tsx` / `BaseCard.tsx`）への反映要否を確認する。通常のカードでは不要。

## 4. ドキュメントを更新する

`CLAUDE.md` の「カードデッキ構成」の枚数表（惑星編 or 秘密基地編）に、追加・変更したカードと枚数を反映する。合計枚数の記述があれば併せて更新する。

## 5. 型チェックと動作確認

- 編集後は型チェックが通ること（PostToolUse フックが `tsc --noEmit` を自動実行する）。
- 必要なら `restart-dev` スキルでサーバーを再起動して動作確認する。
